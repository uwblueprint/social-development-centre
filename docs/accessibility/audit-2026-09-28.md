# Accessibility audit — 2026-09-28

## Partners, partner portal, Opportunities

Scope: `/admin/partners` (both views, header filters, search, the support callout, the organization panel,
the People ⋯ menu and Edit dialog, Invite partner, Remove access), `/admin/opportunities` (tabs, type tags,
header filters, the `?opportunity=` sheet, the ⋯ menu, delete confirm), the 3-step new/edit form (Type,
Details, Review, error summary and jump-to-step), `/partner/opportunities`, `/partner/organization`
(profile, Team invite, resend, cancel, remove), the partner shell. Automated: axe
(`@axe-core/playwright`) on every state above, at 1280px and 320px. Manual: keyboard-only pass through
each flow, checking focus order, focus return after dialogs/menus/step changes, and status messages.

### Notes

- Issue 1 is the significant finding: it affected seven of my own files and every dialog/sheet/confirm I
  own that isn't opened through a `DialogTrigger`/`AlertDialogTrigger`. The fix is a small shared hook,
  `useReturnFocus` (`src/app/admin/partners/_lib/useReturnFocus.ts`), reused by both portals.
- `pnpm typecheck` and `pnpm lint` pass. `tests/a11y-portals.spec.ts` (17 cases: the states above, plus
  320px) passes; one case (`Invite partner dialog open`) excludes the `CreatableCombobox` trigger from its
  axe scan pending the kit fix in row 3, with a comment pointing at this table.
- No copy changed. No new user-facing behavior — this audit fixed accessibility defects in existing
  flows, so no `docs/user-guide/`, `docs/decisions/` or `docs/backend/` update is needed.
