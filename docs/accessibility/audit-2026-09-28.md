# Accessibility audit — 2026-09-28

## Partners, partner portal, Opportunities

Scope: `/admin/partners` (both views, header filters, search, the support callout, the organization panel,
the People ⋯ menu and Edit dialog, Invite partner, Remove access), `/admin/opportunities` (tabs, type tags,
header filters, the `?opportunity=` sheet, the ⋯ menu, delete confirm), the 3-step new/edit form (Type,
Details, Review, error summary and jump-to-step), `/partner/opportunities`, `/partner/organization`
(profile, Team invite, resend, cancel, remove), the partner shell. Automated: axe
(`@axe-core/playwright`) on every state above, at 1280px and 320px. Manual: keyboard-only pass through
each flow, checking focus order, focus return after dialogs/menus/step changes, and status messages.

### Notes

- Issue 1 is the significant finding: it affected seven of my own files and every dialog/sheet/confirm I
  own that isn't opened through a `DialogTrigger`/`AlertDialogTrigger`. The fix is a small shared hook,
  `useReturnFocus`, moved to `src/lib/useReturnFocus.ts` (it started in
  `src/app/admin/partners/_lib/`, but `src/features/opportunities/` already needed to reach across that
  app-route folder to use it — moved so feature code doesn't import from an app route). Reused by both
  portals; imports in `PersonActions.tsx`, `PartnersView.tsx` and `OpportunitiesView.tsx` updated.
- `pnpm typecheck` and `pnpm lint` pass. `tests/a11y-portals.spec.ts` (17 cases: the states above, plus
  320px) passes with no exclusions, including "Invite partner dialog open" now that row 3 is fixed.
- No copy changed. No new user-facing behavior — this audit fixed accessibility defects in existing
  flows, so no `docs/user-guide/`, `docs/decisions/` or `docs/backend/` update is needed.

## Kit, shell, sign-in, Community, kiosk

Scope: `/components`, `/login` (default and `?signedOut=1`), `/kiosk` (form, validation error, success
with countdown), `/admin/community` (both tabs, search, the Status filter, sort, the member sheet and its
actions), the admin shell (sidebar, mobile drawer at 320px, My account dialog), and every dialog/menu/
popover reachable from Community (Add members — single and import views, Export, the kiosk-launcher
dialog, the member sheet's convert/delete confirms, the row ⋯ menu). Automated: axe
(`@axe-core/playwright`) on every state above plus each one opened via a real click/keyboard flow, not
just on page load. Manual: keyboard-only pass through each flow (focus order, return, traps), contrast
computed from `tokens.ts` and cross-checked live via axe's `color-contrast` rule (which measures the
actual rendered/blended color, catching cases the token table alone wouldn't), and a real ArrowRight/Tab
walk through the 320px tab list to confirm focus lands somewhere visible.
