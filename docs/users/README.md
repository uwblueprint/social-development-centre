# Users

Who we build for. Read the file for a user before you design a screen they'll touch. The facts come from the Notion workspace (see [product context](../product/README.md)). Anything marked **Assumption** hasn't been confirmed with SDC.

| User | How many | Where they use the product | File |
|---|---|---|---|
| SDC admin | 2–10 | Admin portal (`/admin`) | [sdc-admin.md](sdc-admin.md) |
| Civic Hub partner | ~50 organizations, several people each | Partner portal (`/partner`) | [civichub-partner.md](civichub-partner.md) |
| Community member | ~900 subscribers | Email only, no account | [community-member.md](community-member.md) |
| Paying member | 120–150 | Email, plus a members-only feed later (P2) | [paying-member.md](paying-member.md) |
| Invited friend | Grows with referrals | A share link that goes to the partner's page | [invited-friend.md](invited-friend.md) |

## The one rule that follows from all of them
Every feature should **remove work before it adds capability**. Student-built tools fail when they create new admin chores. SDC has already watched three directory projects fail to launch.
